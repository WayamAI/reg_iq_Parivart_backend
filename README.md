# PARIVART Backend

Enterprise Regulatory Change Intelligence platform backend.

## Technology Stack
- **Language**: Python 3.14
- **Framework**: FastAPI 0.141
- **Database**: PostgreSQL with SQLAlchemy 2.1 Async
- **Migrations**: Alembic (`migrations/`)
- **Security**: JWT (python-jose), bcrypt (used directly, not via Passlib)
- **Validation**: Pydantic v2

## Quick Start

```bash
# Setup virtual environment
python3 -m venv .venv
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Copy and configure environment
cp .env.example .env
# Edit .env with your DATABASE_URL and JWT_SECRET

# Create tables, add any missing columns, and seed demo data (idempotent)
python -m scripts.init_db

# Run uvicorn directly for development
uvicorn app.main:app --reload --port 8010
```

## Database

Schema changes are Alembic migrations. The migration environment reads its URL from
`app.core.config.settings`, so it always targets the same database the API is configured
for.

```bash
alembic upgrade head                      # bring the database up to date
alembic current                           # what the database is stamped at
alembic downgrade -1                      # step back one revision
alembic check                             # fail if the models have drifted from the schema
alembic revision --autogenerate -m "..."  # draft a revision from model changes
```

Always read an autogenerated revision before committing it. Autogenerate adds NOT NULL
columns outright, which fails on a populated table, and emits unnamed constraints that
cannot be dropped on downgrade.

Bringing an already-running database under Alembic for the first time: stamp it at the
revision matching its current shape, then upgrade.

```bash
alembic stamp 0001_baseline
alembic upgrade head
```

`scripts/init_db.py` remains for local development convenience -- it creates tables, adds
missing nullable columns, and seeds demo data:

```bash
python -m scripts.init_db            # create tables + add missing columns + seed
python -m scripts.init_db --no-seed  # schema only
python -m scripts.init_db --check    # report drift, exit non-zero if any
```

It is additive only and never drops or alters an existing column. Use a migration for
anything else; `alembic check` is the authoritative drift check.

## Error contract

Every error response carries an `X-Request-ID` header and a JSON body of the form:

```json
{
  "error": { "code": "INTERNAL_SERVER_ERROR", "message": "...", "request_id": "..." },
  "detail": "..."
}
```

`detail` is retained for backwards compatibility; `error.code` is the stable value clients
should switch on. Unhandled exceptions are converted to a 500 *inside* the CORS middleware,
so the browser can always read them -- a failed API call is distinguishable from an
unreachable backend (which produces no HTTP response at all). `/health` never touches the
database or an AI provider, so it stays a reliable reachability probe.

## Testing

```bash
pytest          # the whole suite, against in-memory SQLite with foreign keys enforced
```

Tests never reach a real database or an AI provider: `app/tests/conftest.py` pins the
environment before `app.core.config` is imported anywhere, and every AI provider is mocked.
